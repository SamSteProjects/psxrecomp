# Independent importer restoration and model preview

Restored our Python importer, CLI, tests, and v2 metadata schema from
`legaia-sdk-integration` (`28ce54367127e858c8ef2bfbd27ffe64f60e0e93`).
This is our prior implementation, not code copied from Andrew's repository.

The research reference remains `AndrewAltimit/legend-of-legaia-re` at
`d6e64c68ede25813d35db20980da82a1a025549b`. This revision was inspected with
`git show` in the read-only local reference checkout. No dependency or revision
change was introduced. Source references examined:

- `crates/prot/src/cdname.rs`: `block_range_for_name_extraction`, raw TOC index
  minus two, including header-row exceptions.
- `crates/asset/src/scene_asset_table.rs` and
  `crates/engine-core/src/scene_bundle.rs`: count-six/count-seven descriptors,
  sector-aligned embedded tables, MAN carrier and extended entry offsets.
- `crates/asset/src/man_section.rs`: P1 placement records, record-zero controller,
  local-prefix bounds and X/Z coordinate formula. Runtime function references
  are `FUN_8003A1E4` and `FUN_8003D0BC`.
- `crates/tmd/src/lib.rs`: relative TMD object pointers from the 12-byte header,
  28-byte object descriptors and signed 16-bit vectors.
- `crates/tmd/src/descriptor.rs` and `legaia_prims.rs`: grouped primitive layout,
  known renderer mode rows, byte-offset vertex indices, flat/Gouraud colors,
  UV/CLUT/texture-page fields and lit versus baked-color packet differences.
  Underlying retail references: `FUN_8002735C`, `FUN_80029888`, `DAT_8007326C`.
- `crates/tmd/src/mesh/basic.rs`: object-local coordinate treatment and the PSX
  quad diagonal (v0,v1,v2), (v1,v3,v2).

The preview parser is independently written Python. Unknown magic, relocated
pointers, unknown primitive modes, invalid indices and over-budget inputs fail
explicitly. No guessed pose or object transform is applied. The object table's
last word stays opaque. UVs and materials are decoded, but texture pixels,
skeletal pose, animation and runtime lighting are not reconstructed.

`import_scene(disc, scene)` retains `legaia.scene-import.v2` and stable actor/model
identities. Importer version is 0.3.0. Exact CDNAME labels replace the town01 gate,
source locators use the selected scene, and structurally unsupported scenes fail
explicitly. `list_scenes(disc, offset=0, limit=64, prefix='')` examines at most
128 CDNAME blocks per call and distinguishes placement-readable scenes from
unchecked model resolution. Reference runtime interpretations are labeled as
reference evidence, not live traces performed by this importer.

Actual user-owned SCUS-94254 retail validation on 2026-09-09:

- town01: 52 actors, 119 models, 52 resolved model references; two imports match.
- town0c: 44 actors, 115 models, 44 resolved model references.
- Catalog prefix `town`: town01/0b/0c/0d/0e found with 52/58/44/39/34 actors.
- rikuroa: explicit unsupported MAN-carrier error; dungeon coverage is not claimed.
- Geometry previews: town01 scene models 0088 (304 vertices, 328 triangles),
  0089 (48/86), 0090 (40/76), and global-special 00f0 (298/544), all without
  primitive-count discrepancies. All 29 unique models referenced by town01's
  actors decoded successfully in the subsequent bounded coverage pass.
- 23 importer tests passed, including the actual retail determinism/bounds test
  and synthetic geometry, UVs, colors, quad order, malformed input and source
  locator tests.

Private outputs reside beneath ignored `local-output/sdk-20260909`; no retail
payload or geometry fixture was added to tracked sources. `load_model_preview`
verifies the source disc hash before resolving the exact imported model span.
Metadata import and geometry preview are intentionally separate APIs: the
metadata-only output guard continues rejecting mesh/payload byte fields.
