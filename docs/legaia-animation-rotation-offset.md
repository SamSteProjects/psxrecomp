# Retained animation rotation offsets

Open an authored retained animation from the project Asset Database, then **Edit retained content → Frame sequence tools**. Choose the inclusive output frame range and the existing rigid object. Enter **Rotation offset X/Y/Z**, then **Stage rotation offset**. **Review retained edit → Preview reviewed content → Apply reviewed content** uses the existing retained-content workflow; Save/Open and Undo/Redo retain the result. Other actors referencing the same clip remain governed by the existing review/reference service.

Offsets are exact native PSX angle units, multiples of 16 from -4080 through 4080. A turn is 4096 units. Each selected effective axis becomes `(before + delta) modulo 4096`, on the original 0..4080 grid. The base includes the frozen captured donor, current frame mapping and local channel drafts. Zero axes preserve inheritance and create no new channel contributions. Blank/fractional/off-grid values, full-turn ±4096, stale source and out-of-range frame/object identities refuse. This operation adds encoded rigid Euler-axis values; it does not compose world-space or quaternion rotations or infer anatomical joints, skeletal parenting or playback timing.

Translations, unselected rotation axes, objects and frames, frame mapping, opaque channel nibbles, header and trailer remain held. The captured donor stays immutable. Staging returns a detached draft and makes no project/history change. A subsequent fresh Review is required before Apply. Existing authoring bounds, revision budgets, native serialization, initial reference validation, pending locks, disposal and stale-response withdrawal are reused. No new project format or runtime writer is added.

`POST /api/animation-record-rotation-offset` accepts the same exact source-bound draft/range fields as translation offset, with rotation-grid deltas. The shared staging service chooses the native rotation field and wrapped arithmetic; the original translation API preserves its signed twelve-bit overflow refusal. The client validates the receipt schema, source identities, before/after edits, every changed axis and native hashes before accepting a staged result.
