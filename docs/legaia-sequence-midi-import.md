# Import Matching-Layout MIDI Operands

In the **Sequence operand editor**, export **Current MIDI**, edit the MIDI operands in another tool, then choose **Import matching-layout MIDI**. An unchanged file stages no draft. Changed operands enter the existing **Review sequence operands** and **Apply sequence operands** workflow; uploading alone never changes Current or project history. Discard cancels the draft.

This import targets the existing native fixed-width SEQ writer. The file must be one complete Standard MIDI File format-0 track with matching PPQN, event count/order, channel/status, delta ticks and ending. It must retain the exported initial tempo and time-signature anchors. Notes, velocities, pressures, controllers, programs, pitch-bend operands and encoded tempo events may change. There is a limit of 256 changed events and a 512 KiB track budget. Channel running status is decoded; meta events clear it. These conventions follow the [Standard MIDI File specification](https://midimusic.github.io/tech/midispec.html).

Unsupported metadata, SysEx/system messages, multiple tracks, SMPTE division, extra chunks, malformed/truncated events, header changes, event insertion/removal and timing changes are rejected explicitly. No track merging, quantization, resampling, instrument conversion or audio synthesis occurs. General sequence replacement remains unfinished because the native authoring codec currently preserves all source event boundaries and opaque carrier bytes.

The original file is read without modification. Reviewed native operand edits and retained MIDI source receipts are separate project sections. Use the input retention controls below to preserve the original file. Project-wide MIDI Asset Database indexing and broader native sequence allocation remain open buildout work. Source ownership and stale project checks reuse the existing sequence authoring service. Retail and Current remain separate.

## Retain and Recover MIDI Inputs

After importing a matching-layout MIDI file, choose **Review MIDI input retention**, then **Retain reviewed MIDI input**. Retention saves the original bytes at `Authored/Audio/MidiSources/<sha256>.mid` and registers a historical retail-target receipt. It changes no native operands and clears the local operand draft during refresh. Choose the receipt in **Retained MIDI input**, then use **Save retained MIDI input** for exact recovery or **Stage retained MIDI operands** for a fresh Current draft requiring native Review/Apply.

A receipt records global audio identity, imported capture scene, exact retail PROT/SEQ provenance, MIDI hash/length, canonical retail-relative operand mapping and complete candidate SEQ hash. The SDK independently replays the retained file against fresh retail bytes when validating, recovering, saving, reopening or generating a Build sidecar. This requires the configured retail disc and imported source scene. Receipts do not assert Current usage, runtime instruments or game playback. Native overrides remain independent. The collection permits 32 receipts and 16 MiB of unique MIDI bytes. Re-retaining an identical target/input receipt is a no-op. Undo unregisters the receipt while preserving the content-addressed file for Redo; no automatic file deletion occurs. Project-wide MIDI Asset Database indexing remains unfinished.

Native Build input identity includes the receipts and preserves exact MIDI files plus a hashed manifest under `midi-inputs/<authored_state_key>/`. These historical sidecars are separate from installable native payloads. Review locks competing edits and selection. **Discard operand draft** cancels the removal proposal. Removal unregisters only that receipt; the original file and native operands remain unchanged. Shared receipts keep their registered byte allocation; removing the last receipt releases accounting space while preserving the physical file. Undo/Redo and Save/Open retain those semantics.
