# Pinned asset metadata comparison

Open an Asset Database record's **Details**, choose **Pin metadata**, then inspect another record and choose **Compare pinned metadata**. The dialog shows differing recorded fields by default; **Show equal fields** includes the matching fields. **Save comparison evidence…** downloads both complete snapshots, their source contexts and the qualified difference rows. **Clear pinned metadata** removes the temporary pin. Pinning another record replaces it. Pins are session-local and clear on reload; they are not project authoring.

Comparisons use the stable project asset input key, which excludes scene navigation. They can retain a pin across navigation while the same project inputs remain unchanged. A different project or changed inputs withdraw the pin on the next check. Capture/comparison/download also recheck `/api/state` and the current details record; stale, closed or replaced inspection context refuses the action. Recorded memberships and active source scenes remain visible in the evidence. Scene-independent ownership is covered by focused checks; the actual editor proof uses two Town01 actor records.

Object field order is immaterial; arrays retain recorded index order. Missing fields remain distinct from explicit null. Paths escape JSON Pointer separators. A container/type mismatch or missing subtree is represented at its owning field, rather than guessed semantic matching. The complete report is bounded to 512 field rows and 8 MiB; overflow refuses the comparison without claiming a partial result. Long displayed values may shorten at 2000 characters, with their complete value retained in evidence. Existing asset-evidence download remains available for larger records.

This read-only comparison uses SDK catalog metadata, not native geometry/texture/audio bytes, executable behavior, runtime identity or proof of gameplay changes. No relationship, confidence or live use is inferred from a difference. Imported and authored metadata remain in their original layers. Existing source-specific editors and reference navigation remain separate actions in Details.
