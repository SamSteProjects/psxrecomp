# Duplicate an Assigned Animation Clip

An imported actor with an authored allocated initial clip now exposes **Duplicate assigned clip...** through Inspector metadata. The action resolves the exact active retained record by assignment UUID, native hash, captured model and current scene source. It supports a capture originally owned by another actor sharing that model; it does not guess the source by actor name or donor order.

The dialog shows only that source and offers **Review independent duplicate** and explicit **Apply reviewed change**. It reuses the existing retained-record duplication command, source reconstruction, capacity checks and atomic history. Retirement and actor-assignment controls are unavailable in this view. The copy has a new identity, exact retained native content, active status and no actor assignment. The original clip and all existing assignments remain intact. ## Open the New Copy for Editing

After Apply, the Inspector workflow refreshes the asset database and opens the copied retained clip. It uses the duplicate receipt's new UUID rather than the original actor assignment or the first matching donor. The handoff requires one exact asset in the current scene, Edit capability, matching native record and donor hashes, channel/model ownership and frame/object counts, active status and no authored actor assignments. A stale or inconsistent refresh leaves the created copy intact and reports how to find it in the asset database.

The asset view exposes the existing retained-content editor, GLB editor, preview and assignment tools. **Edit retained content** receives the new UUID, so the original assigned record remains separate. Opening the copy does not assign it to an actor or change playback.
