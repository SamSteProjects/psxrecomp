# Asset Category Discovery

Choosing a resource category in the active-scene Asset Database now requests its verified catalog automatically. This covers textures, animations, audio, scripts, dialogue, flag references, transitions, collision, triggers, regions, world-map records and authored retained clips. The existing catalog service supplies stable SDK records and validates source/scene/flag/transition/region/trigger identities before publication. No retail decoder was moved into the editor.

A shared scheduler requests once per current resource source. It reuses a verified catalog across categories, waits for unrelated busy work to finish, and rechecks scene identity, scope, capability and selection eligibility before queued loading. Source changes withdraw the existing catalog through the established lifecycle; a still-selected resource category can then discover the new scene. Switching away from resource categories or into project scope drops queued active-scene work. Existing imported actors/models/scenes remain directly available; the default All category does not launch discovery at startup. Whole-project discovery begins when Project resources scope is selected; see the project-scope section below.

Failures publish the existing source-bound error and stop automatic retries for that source. **Refresh scene resources** explicitly retries or re-verifies; choosing a resource category again can also request a retry. Search rendering and busy-state reconciliation do not create retry loops. Pending requests are deduplicated; the established catalog loader owns aborts and stale-result rejection. Catalog loading changes editor caches, not project authored state or native content.

The catalog help text now describes the implemented source audio bank, sequence and sample tools, with runtime instrument selection and scene playback still explicitly unverified.

## Explicit Resource Searches in All Records

In **All records**, a positive resource type filter such as `type:animation`, or a resource stable ID such as `id:animation://town01/authored-record/...`, now requests the active-scene catalog. Unfielded stable IDs also work. Detection uses the existing bounded asset-query parser and its case-insensitive substring type semantics; it does not replace search matching or infer asset contents. Ordinary name queries, excluded terms, malformed queries and unrelated selected categories do not trigger this discovery. Once loaded, the qualified catalog is reused across searches. Project-scope resources use their own verified inventory, discovered when that scope is selected.

The search path shares the category scheduler, capability/source/scope/busy guards, pending deduplication and explicit retry policy. Queued work rechecks the current query's eligibility before loading. Search typing does not reset a failed source's retry state.

## Project Scope Discovery

Choosing **Project resources** now loads the verified inventory across imported scenes without a second Refresh action. The default Active scene resources scope does not request whole-project discovery. The project catalog keeps its existing detached service, per-scene variants, coverage limits, metadata budgets, pagination and source-qualified inspector navigation. It shares the discovery scheduler with active-scene loading while retaining separate caches and request ownership.

A verified inventory is reused when returning to project scope. Persisted-source changes withdraw it and schedule discovery for the current project when unrelated editor work finishes. Queued reads recheck scope/source/busy/pending guards. Leaving project scope aborts a pending read; old completion cannot publish or release another operation's busy token. Failed reads wait for **Refresh project resources** or leaving and reentering Project resources. Search, category changes and rendering do not retry a failure. This also holds when manual Refresh fails before an already queued automatic read starts. Disposing the controls drops scheduled work.
