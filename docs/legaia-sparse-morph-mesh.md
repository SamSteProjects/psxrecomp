# Sparse Saved GLB Morph Pose Import

The model **Import GLB mesh** workflow now accepts sparse FLOAT VEC3 POSITION/NORMAL/TANGENT target deltas. Upload, Review Current/Proposed, Apply, retained original GLB/settings, one history command and Save/Open use the existing SDK services. No additional manual conversion is required. Donor, scene, scale, origin and rotation changes still invalidate Apply.

Sparse accessors initialize from their dense base buffer view, or zeros when that view is absent, then replace the indexed elements. Unsigned byte, short and integer index formats are supported. Indices must be strictly increasing, unique and below the base vertex count. Embedded index/value views must have valid extents/alignment and no stride or target; dense initialization may remain interleaved. Values must be finite. Metadata, missing fields, extensions, unsupported types, range/order/alignment violations and decoded component-budget overflow reject before mutation. This follows [Khronos glTF Sparse Accessors](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#sparse-accessors), sections 3.6.2.3, 5.2–5.4. Replacement happens before morph weighting and skin/node transforms. Native tangents remain unsupported and are qualified but ignored, as in dense import.

The existing eight-target/8192-source-vertex bounds and native allocation budgets remain. This feature is isolated in `model_mesh_sparse`; fixed-layout source-identity GLB import, base mesh attributes, skin influences/inverse binds and animation accessors keep their existing sparse refusals. It does not add animated morph sampling, native morph controls, skeletal animation or retail structure guesses.
