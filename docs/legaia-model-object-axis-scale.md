# Whole-object axis scaling

Open **Model → Edit vectors → Scale whole object by axis**. Enter separate integer X/Y/Z percentages from 1 to 1000 and choose **Local origin** or **Current bounds center**. **Preview whole object axis scale** obtains a fresh source-qualified proposal; compare Current/Proposed geometry and source normal directions, or inspect one supported scene instance. Apply remains disabled until the exact inputs have a changed, verified proposal. Editing an input, changing the object/source, closing the editor or returning from scene inspection withdraws that proposal. Review again before **Apply reviewed object axis scale**.

The operation scales all stored vertices in that object. For bounds-center scaling, the pivot is computed from the Current vertex extrema; doubled integer pivot coordinates preserve half-unit centers until final rounding. Positive scale excludes reflection and singular transforms. Final vertex words round halfway away from zero. Any signed 16-bit overflow rejects the entire operation before persistence.

Stored normals use the inverse transpose: an XYZ direction is divided by the corresponding scale factors, then adjusted to its original stored magnitude before rounding. This preserves direction correctly under nonuniform scale without assuming a canonical retail normal length. Exact integer square comparisons implement nearest-word rounding, with halves away from zero. Actual final lengths can vary slightly after integer quantization. Zero normals stay zero; an object with no normals is supported. Uniform positive scale keeps every normal word exactly unchanged. Normal overflow also rejects the entire operation. Each object is bounded to 1..8192 vertices and at most 8192 normals.

The client independently recomputes exact vertex/normal words and checks the complete Current/Proposed word arrays, operation inputs, object ownership, unchanged triangle data and scalar-change kinds before publishing a preview. `POST /api/model-object-axis-scale` requires the exact asset/object/percent/pivot fields and both inspected and reviewed proposed hashes. The project reconstructs the candidate, rechecks that receipt, and commits through the existing model-replacement command only if bytes changed. A 100% identity does not create history. Undo/Redo, Save/Open and Build use existing native model ownership and persistence; no new project format is introduced. This edits the shared model object, so all referring instances use the authored asset.
