# Actor and NPC Ground Position Proposals

Existing imported actors and authored NPC drafts now offer **Choose position from scene ground** in their Inspector. The shared picker supplies qualified native X/Z into a detached proposal. The Inspector shows Current and Proposed coordinates, with explicit **Apply picked X/Z** and **Discard picked position**. Returning without a point preserves the prior proposal. The existing numeric property editors remain available.

The reusable Inspector control binds Project copy source, scene preview source, target identity, selection and current position. Picking owns a current-target callback, so changing selection cancels it even when the serialized Project source key stays unchanged. A detached or stale Inspector cannot receive a late result or steal focus. Proposal controls permanently withdraw on changed context; removing the Inspector disposes its timer. Creation continues using the same picker with its original form/Return labels.

Application uses the existing Project commands: imported actors receive one X/Z-only `set_transform`, and NPCs receive `set_actor_draft_position`. The native 64-unit grid and encoding bounds are enforced by the ground adapter and existing SDK service. No Y, heading, donor, script or other property is added to the command. Retail geometry and imported placements remain separate; picking and Discard do not mutate the Project. History, Save/Open and serialization ownership remain with the SDK.

Verification found two editor-shell issues. The desktop command row could overflow the whole document, scrolling the scene off-screen when controls received focus. Overflow is now contained inside the command toolbar. On narrow screens, fixed header height let wrapped commands overlap panel tabs; a flex layout now reserves actual header height and keeps long command rows scrollable. These changes preserve the existing panels and controls.
