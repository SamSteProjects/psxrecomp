# Source Script Walkthrough

Open a script resource in the Asset Database, choose **Inspect script**, expand **Instruction paths**, then **Walk through source instructions**. This walkthrough uses the verified Retail source report already shown in that workspace. It shares selected boundaries with the instruction table and branch inspector, while retaining its own trace.

Choose **Start at source entry**, or select a decoded instruction and choose **Start at selected instruction**. Each **Follow** button identifies one encoded successor and its condition label. Clicking it records your explicit choice. Conditions and flags are not evaluated, and waits, movement, dialogue, effects and external resumption do not execute. This is a source inspection tool, not a game VM or authenticated runtime trace. The branch workspace also supports separate Current and reviewed Proposed walkthroughs, described below.

**Back one walkthrough step** removes the last chosen visit; **Reset walkthrough** clears the trace. Starting again replaces the previous trace. Cycles retain repeated visits rather than being treated as proof of an infinite runtime loop. An undecoded target is recorded once and stops further stepping; a boundary with no encoded successor leaves runtime resumption unknown. After 1,024 visits, further stepping is refused until Back or Reset. The panel shows the last 32 visits, with the complete bounded trace retained for export. Visit buttons inspect their source boundary; selecting elsewhere does not implicitly change the trace.

**Download source walkthrough** writes metadata with project/scene/script identity, the source record SHA-256, captured project input key, every visited boundary and chosen successor index/condition, stop state and explicit unevaluated/runtime-unasserted flags. Download freshly re-reads the Retail record and authoritative project state before publishing. Traversal locks during this check; a failure clears the trace and disables export until inspection is reopened. Original script bytes are not included. The record hash can be checked against the workspace's original source bytes. Export does not make the path a gameplay execution claim.

Busy controls refuse actions. A changed source/project/scene context clears the trace and disables actions until inspection is reopened. Closing the dialog or replacing its report disposes the panel and its freshness timer. No project command, history entry, Build, Run or runtime write is issued by this feature.

## Current and Proposed Script Walkthroughs

In the script branch workspace, choose **Walk through Current flow** to inspect decoded flow including inherited and authored branch values. Review a branch change or reset through the existing review controls, then choose **Walk through reviewed Proposed flow** to inspect that independently reviewed proposal before Apply. Both use the same explicit successor choices, Back/Reset and bounded visit history as the Retail walkthrough. Conditions and instruction effects remain unevaluated.

Walking highlights instructions without switching the branch being authored. A Current trace survives reviewing a draft. Discarding or changing the accepted proposal withdraws its Proposed trace; refreshing the branch snapshot withdraws either trace. Closing inspection disposes the walkthrough and its freshness timer.

The download uses schema `legaia.script-source-walkthrough.v2` for these two representations. It retains the original Retail record hash as provenance, and separately records the script authoring state key and SHA-256 of the complete canonical decoded flow report. **The report hash is metadata identity, not a native byte hash.** Proposed evidence additionally identifies the exact branch, reviewed value (including a Retail reset) and review key.
