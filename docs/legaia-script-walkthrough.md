# Source Script Walkthrough

The shared hypothetical sandbox also supports [Local Flag Mask Simulation](legaia-script-local-masks.md) for normal `4C 35/36`, with partial unknown-bit preservation, visible mask traces and existing Back/scenario replay. Other field-state host effects remain unsupported.

Open a script resource in the Asset Database, choose **Inspect script**, expand **Instruction paths**, then **Walk through source instructions**. This walkthrough uses the verified Retail source report already shown in that workspace. It shares selected boundaries with the instruction table and branch inspector, while retaining its own trace.

Choose **Start at source entry**, or select a decoded instruction and choose **Start at selected instruction**. Each **Follow** button identifies one encoded successor and its condition label. Clicking it records your explicit choice. Conditions and flags are not evaluated, and waits, movement, dialogue, effects and external resumption do not execute. This is a source inspection tool, not a game VM or authenticated runtime trace. The branch workspace also supports separate Current and reviewed Proposed walkthroughs, described below.

**Back one walkthrough step** removes the last chosen visit; **Reset walkthrough** clears the trace. Starting again replaces the previous trace. Cycles retain repeated visits rather than being treated as proof of an infinite runtime loop. An undecoded target is recorded once and stops further stepping; a boundary with no encoded successor leaves runtime resumption unknown. After 1,024 visits, further stepping is refused until Back or Reset. The panel shows the last 32 visits, with the complete bounded trace retained for export. Visit buttons inspect their source boundary; selecting elsewhere does not implicitly change the trace.

**Download source walkthrough** writes metadata with project/scene/script identity, the source record SHA-256, captured project input key, every visited boundary and chosen successor index/condition, stop state and explicit unevaluated/runtime-unasserted flags. Download freshly re-reads the Retail record and authoritative project state before publishing. Traversal locks during this check; a failure clears the trace and disables export until inspection is reopened. Original script bytes are not included. The record hash can be checked against the workspace's original source bytes. Export does not make the path a gameplay execution claim.

Busy controls refuse actions. A changed source/project/scene context clears the trace and disables actions until inspection is reopened. Closing the dialog or replacing its report disposes the panel and its freshness timer. No project command, history entry, Build, Run or runtime write is issued by this feature.

## Hypothetical Flag Sandbox

Inside a Retail, Current or reviewed Proposed walkthrough, expand **Simulate hypothetical flag words**. Supply local (16-bit), global (32-bit) and context (32-bit) words in hexadecimal, or leave a bank blank to retain unknown bits. Start at entry or the selected decoded instruction. **Simulate one instruction** executes one supported temporary operation; **Simulate until boundary** advances until an unsupported/unknown/wait boundary or the 256-instruction limit. Back restores the complete prior PC and known/value masks. Reset clears simulation; changing input fields affects the next Start, not the current state.

This is an initial single-context interpreter slice, separate from manual successor traversal. It supports qualified non-extended NOP and JMP_REL plus L/G/CFLAG SET, CLEAR and TEST, and the flag-word branches described below. SET/CLEAR resolve only their addressed bit when the rest of a bank is unknown. TEST advances only when that bit is known and set; a known clear bit waits at its PC, while an unknown bit stops with an explicit unknown state. Bit 31 uses unsigned 32-bit values. Local bits 16–31 retain unresolved width semantics. Extended contexts, CFLAG SET bit 8 (actor-field copy), CFLAG CLEAR bit 10 (halt lifecycle), dialogue, system selectors, other conditions and host instructions stop without applying or skipping their effects. Dialogue remains a known unsupported boundary. There is no implicit scheduler resume, actor movement, audio, menu execution or runtime attachment.

Closing, refresh, stale context and busy/export ownership withdraw or disable the temporary simulator through the existing workspace lifecycle.

## Hypothetical Flag-Word Branches

The encoded selector is masked to five bits. A known set bit chooses the decoded `flag_bit_set` successor; a known clear bit chooses `flag_bit_clear`. An unknown bit leaves the PC unchanged and stops without choosing either successor, even when both encoded destinations are equal. Branching does not mutate any word. The inspector shows the predicate, bit and resulting PC; it retains at most 256 simulated steps and displays the last 16 branch decisions with an explicit truncation notice. Back removes the decision and restores the exact prior state.

## Explicit Hypothetical Frame Waits

A qualified non-extended `WAIT_FRAMES` can now stage an explicit timing boundary in the same sandbox. Supply **Initial wait accumulator** in signed decimal (`-32768..32767`) before Start, or leave it blank to retain unknown state. Start with an unknown accumulator stops at the wait without inventing zero. **Simulate until boundary** stops when a wait is staged; it does not repeatedly resume it or advance any clock.

Enter **Simulated tick delta** and choose **Advance one simulated tick** to perform one hypothetical WAIT evaluation. The delta is the signed16 value after the reference host's native cast, not seconds or a measured frame interval. The accumulator saturates within signed16. A value below the decoded target retains the same PC and waits for another explicit tick; completion resets the accumulator to zero and advances to the qualified continuation. Zero and negative deltas remain explicit hypotheses. Targets above 32767, unresolved/extended context, inconsistent decoder metadata and other host effects refuse. This reproduces the pinned `crates/engine-vm/src/field/step.rs` opcode `0x4A` arithmetic for supplied assumptions; actual game scheduling and host delta values are unverified.

Back restores PC, accumulator, waiting status, words and history before the selected step. Editing the initial accumulator affects the next Start; each tick input is sampled only on its explicit click. The 256-step limit includes staging, simulated ticks and stop attempts; staging itself performs no native tick arithmetic. The display shows the last eight tick outcomes with an explicit truncation notice, including intermediate saturation and completion reset. Busy/export ownership, stale context, refresh and close use the existing sandbox lifecycle. Manual source trace downloads still exclude all sandbox state.

## Explicit Hypothetical Bit Assumptions

After Start, choose **Assumption bank**, a decimal bit index and **Set**, **Clear** or **Unknown**, then choose **Set hypothetical bit**. This edits one temporary assumption in a ready or flag-blocked sandbox. Local indices are 0–15; global and context indices are 0–31. Set/Clear resolves only that bit, preserving all other values and known masks. Unknown withdraws only that bit's knowledge and clears its stored placeholder value. It does not infer story state, write imported/authored/live values, run another context or invoke a scheduler.

The action stays at the same PC and makes a flag-blocked sandbox ready for a separate explicit instruction step. A TEST may still stop if its tested bit is clear or unknown; a flag-word branch chooses a successor only after its predicate is known. Existing unsupported-context, host-effect, wait and undecoded boundaries cannot be bypassed by this action. Native halt/reactivation ownership remains unresolved. The pinned Andrew TEST handlers (`crates/engine-vm/src/field/step.rs`, revision `d6e64c68ede25813d35db20980da82a1a025549b`) return Halt for a clear bit; this tool is a user-directed hypothetical re-evaluation, not evidence of actual scheduler resume.

Each assumption is one of the maximum 256 sandbox steps. Back restores the exact prior word, known mask, PC and blocked status. The display retains the last eight assumption summaries with an explicit truncation notice. Busy/pending source requalification, stale context and disposal guards apply to the controls. No clock advances and no automatic instruction executes.

Saved scenarios containing these actions use `legaia.script-sandbox-scenario.v2` and typed `assume_flag` events with exactly bank, bit and boolean/null value. Load independently replays these events before comparing the final state and applying the existing fresh SDK source checks. Version-1 files still load; instruction/tick-only saves remain version 1. Version 1 refuses assumption events. Scenario replay checks consistency, not cryptographic authenticity of user assumptions: different explicit recipes can legitimately reach the same result.
