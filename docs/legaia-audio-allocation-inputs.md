# Retained resized sample inputs

In a source audio bank, open **Edit sample → Resized WAV inputs**. Choose a mono signed16 WAV, then **Review resized WAV → Retain reviewed resized WAV**. Review displays source/input frame counts, sample byte sizes, the carrier delta, preserved start-block ordinals, encoding error and candidate hashes. **Discard resized draft** leaves Current unchanged. Retention stores the exact original WAV and its source-qualified historical receipt; it does not change the native sample or apply a package.

The same dialog lists retained allocation inputs for the chosen source sample. **Save resized input WAV** independently verifies the exact RIFF/PCM fields and content hash before recovery. **Review resized input removal → Remove reviewed resized input** removes the registration in one history step and keeps the original file. Discard cancels removal. Refresh withdraws stale drafts and rereads registered inputs; a changed native target requires closing and inspecting that sample again. Pending operations lock controls; disposed or stale replies cannot publish a review or recovered file. The parent fixed-size sample editor becomes stale when retention changes project inputs and can be refreshed afterward.

These receipts use `legaia.audio-sample-allocation-source.v1`. They retain the existing content-addressed WAV path, source entry/bank/sample identities, complete input frames/rate, candidate sample hash and review/receipt hashes. The typed schema prevents accidental use in fixed-size Apply. Existing fixed-frame receipts, commands and their client contract remain unchanged. Resized inputs appear as ordinary retained WAV assets in the central Asset Database, including source-target receipts and verified recovery; they do not assert a Current native binding.

`POST /api/audio-sample-allocation-source-review` and `/api/audio-sample-allocation-source-retain` require the same exact source and input fields as the existing fixed-frame input routes; Retain also binds the review key. They use the explicit allocation codec contract rather than inferring a mode from file length. Inputs are bounded to 1 MiB; the HTTP routes allow their bounded base64 envelope. Retain reconstructs the review before writing, qualifies the original content-addressed file and commits one `audio_sample_sources` history entry. Undo/Redo, Save/Open, project copy and export snapshots reuse the existing project representation. Frozen Build WAV input sidecars also preserve and recover typed allocation receipts; this is historical input preservation, not native package or gameplay acceptance.

The [allocation foundation](legaia-audio-sample-allocation.md) provides the encoder/carrier rules: 1–4096 complete 28-frame blocks; encoded non-repeating ends; unchanged start-marker ordinals and post-end tails; no resampling, marker remapping or loop/sustain allocation. Input rate is metadata only. Review uses the immutable Retail target, keeping its candidate separate from any existing Current fixed-size sample edits.
