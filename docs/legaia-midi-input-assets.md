# Retained MIDI Inputs in the Asset Database

Choose **Project resources** under **Asset database scope**, then **Refresh project resources**. Retained MIDI files appear in the **Audio** category as **MIDI Input** records. Search by their stable `audio-input://legaia/midi/<sha256>` identity. Open Details and choose **Inspect retained MIDI input** to inspect verified file metadata, historical capture targets and explicit Current authored replacement inputs, or **Download MIDI input** to recover the exact original bytes.

Each unique registered file has one content identity. Scene memberships come from retained capture receipts and active sequence replacement bindings and refer to imported scene context, rather than runtime residency or the origin of the external file. The inspector shows format-0 PPQN, encoded MIDI event count/ticks, file length/path/hash and each target's retail PROT/SEQ and historical candidate hashes. The count includes the exported initial MIDI metadata anchors. Historical receipts alone do not assert Current input usage. Explicit full replacement bindings identify the MIDI file supplying authored native output; runtime binding, instruments and gameplay acceptance remain unverified. Native operand authoring remains in the [sequence editor](legaia-sequence-midi-import.md).

The SDK independently requalifies every registered receipt and file before indexing and again before inspection/download publication. An input disappears from the inventory when neither a capture receipt nor an active replacement binding registers it; physical files remain available for Undo/Redo. Content tampering, conflicting metadata, unknown identities and stale project keys refuse. The read-only endpoints `/api/midi-input-inspection` and `/api/midi-input-download` accept exactly `asset_id` and `expected_source_key`. No source paths are accepted from callers. Explicit downloads carry bytes separately from the metadata-only project index.

## Current Native Sequence Content

The retained-input inspector compares each historical target candidate with freshly reconstructed Current native SEQ bytes. It shows match/difference, the Current entry and complete SEQ SHA-256 hashes, and the Current sequence offset/size. The comparison uses the receipt's verified capture scene rather than the editor's active scene. Sample allocation can relocate the SEQ carrier; comparison uses its reconstructed Current extent.

A byte match establishes content equality only. It does not prove that a retained MIDI file was used to create an override, that its instrument mapping is correct, or that the game played the sequence. Original input receipts remain historical, and Current/native usage, runtime binding and gameplay verification remain separate. The inspector is read-only; authoring still uses the sequence editor's explicit Review/Apply workflow.

The inspection/download response is `legaia.midi-input-inspection.v2`, with one `current_comparisons` row per qualified historical receipt. The browser validates exact fields, receipt/target ownership, hashes, sequence extents and equality claims. Legacy v1 responses remain decodable without presenting a Current comparison. Fresh project keys and final source/file rechecks guard inspection and exact recovery.

## Historical Native Target References

Open a retained MIDI input's Details and choose **Inspect asset references…**. **Referenced by** lists its historical native audio targets; the native target's **Dependencies** links back to the MIDI input. **Explore references** navigates either direction inside the shared reference panel. **Reference scope → Project** keeps capture-scene memberships visible across imported scenes. The shared filters, provenance details and reference report export retain the same historical relationship.

These links use `retained_midi_sequence_input` with typed `midi_input_evidence`: receipt/input identity, capture scene, native target, disc/entry/SEQ hashes and independently reconstructed historical candidate hash. `input_usage` and `runtime_binding` remain `not_asserted`. A missing native catalog produces an unavailable native endpoint rather than a guessed navigable resource. A byte match shown in the input inspector is separate from this historical relationship.

Retained audio snapshots share file/receipt qualification across scene adapters and recheck MIDI inventory before returning a graph. Source drift, native catalog hash disagreement, unsupported relationship claims and malformed evidence refuse. The graph does not carry original MIDI payload bytes.

## Current Authored Sequence Replacement Inputs

Full sequence replacements now register their retained original MIDI in the shared Audio Asset Database. Details → **Inspect retained MIDI input** shows **Current Authored Sequence Replacement Inputs** separately from historical receipts and historical-candidate byte comparisons. Each binding shows its native audio target, binding scene/hash and independently composed Current entry/SEQ hashes and byte extent. **Download MIDI input** recovers the exact original retained SMF. The active recipe is requalified against its retail owner; a stale key, modified input or reconstructed candidate disagreement refuses publication.

Each MIDI hash has one asset identity, including when both a historical receipt and a full replacement use identical content. Both source relationships remain visible. The representative file path is deterministic; it is not an assertion of external-file origin. Replacement-only inputs use their `Authored/Audio/SequenceReplacements/` file. Clearing a replacement removes its active relationship; a remaining historical receipt still registers the asset. Undo restores the binding, and original retained files are preserved.

**Inspect asset references…** exposes `current_native_sequence_midi_binding` with `current_midi_binding_evidence`, distinct from `retained_midi_sequence_input`. Navigate input → native resource → input with **Explore references**. The relationship establishes authored native output dependency, while `runtime_binding` remains `not_asserted`. Missing native catalogs stay unavailable rather than gaining guessed navigation targets. Inspection DTO v3 supports replacement-only inputs; the client still accepts historical v1/v2 reports.
