# Retained MIDI Inputs in the Asset Database

Choose **Project resources** under **Asset database scope**, then **Refresh project resources**. Retained MIDI files appear in the **Audio** category as **MIDI Input** records. Search by their stable `audio-input://legaia/midi/<sha256>` identity. Open Details and choose **Inspect retained MIDI input** to inspect verified file metadata and historical capture targets, or **Download MIDI input** to recover the exact original bytes.

Each unique registered file has one content identity. Capture-scene memberships come from retained receipts and refer to imported scene context, rather than runtime residency or the origin of the external file. The inspector shows format-0 PPQN, encoded MIDI event count/ticks, file length/path/hash and each target's retail PROT/SEQ and historical candidate hashes. The count includes the exported initial MIDI metadata anchors. Current native usage, runtime binding, instruments and gameplay acceptance are not asserted. Native operand authoring remains in the [sequence editor](legaia-sequence-midi-import.md).

The SDK independently requalifies every registered receipt and file before indexing and again before inspection/download publication. Removed receipts disappear from the inventory even though physical files remain available for Undo/Redo. Content tampering, conflicting metadata, unknown identities and stale project keys refuse. The read-only endpoints `/api/midi-input-inspection` and `/api/midi-input-download` accept exactly `asset_id` and `expected_source_key`. No source paths are accepted from callers. Explicit downloads carry bytes separately from the metadata-only project index.

## Current Native Sequence Content

The retained-input inspector compares each historical target candidate with freshly reconstructed Current native SEQ bytes. It shows match/difference, the Current entry and complete SEQ SHA-256 hashes, and the Current sequence offset/size. The comparison uses the receipt's verified capture scene rather than the editor's active scene. Sample allocation can relocate the SEQ carrier; comparison uses its reconstructed Current extent.

A byte match establishes content equality only. It does not prove that a retained MIDI file was used to create an override, that its instrument mapping is correct, or that the game played the sequence. Original input receipts remain historical, and Current/native usage, runtime binding and gameplay verification remain separate. The inspector is read-only; authoring still uses the sequence editor's explicit Review/Apply workflow.

The inspection/download response is `legaia.midi-input-inspection.v2`, with one `current_comparisons` row per qualified historical receipt. The browser validates exact fields, receipt/target ownership, hashes, sequence extents and equality claims. Legacy v1 responses remain decodable without presenting a Current comparison. Fresh project keys and final source/file rechecks guard inspection and exact recovery.

Three focused Python asset tests, the Node DTO suite on matching and differing real project responses, JS syntax/three Python AST checks and both actual private Town01 browser workflows passed. The match changes after native operand Apply and survives Undo/Redo and Save/Open. Both read-only browser inspections/downloads preserved full document/history/files, recovered exact originals, reported no page errors or mutation/Build/Run requests and fit visually inspected 400 px layouts. Evidence: `local-output/sdk-20260909/midi-current-matches-20261007/` and `matching/`. No game or native Build ran.

## Historical Native Target References

Open a retained MIDI input's Details and choose **Inspect asset references…**. **Referenced by** lists its historical native audio targets; the native target's **Dependencies** links back to the MIDI input. **Explore references** navigates either direction inside the shared reference panel. **Reference scope → Project** keeps capture-scene memberships visible across imported scenes. The shared filters, provenance details and reference report export retain the same historical relationship.

These links use `retained_midi_sequence_input` with typed `midi_input_evidence`: receipt/input identity, capture scene, native target, disc/entry/SEQ hashes and independently reconstructed historical candidate hash. `input_usage` and `runtime_binding` remain `not_asserted`. A missing native catalog produces an unavailable native endpoint rather than a guessed navigable resource. A byte match shown in the input inspector is separate from this historical relationship.

Retained audio snapshots share file/receipt qualification across scene adapters and recheck MIDI inventory before returning a graph. Source drift, native catalog hash disagreement, unsupported relationship claims and malformed evidence refuse. The graph does not carry original MIDI payload bytes.
