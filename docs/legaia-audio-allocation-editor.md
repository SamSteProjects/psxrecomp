# Native sample allocation in the editor

The source VAB bank Inspector now opens **Allocate sample** for each stable source ordinal. This uses the existing native sample editor with an explicit allocation mode. Fixed-frame editing keeps its original routes and validation contract. Allocation has its own exact DTO contract and HTTP routes; it does not infer a mode from WAV length or silently loosen fixed-size authoring.

Choose **Resized WAV inputs** to review/retain an original mono PCM input using the existing metadata workflow. Back in allocation mode, Refresh rereads retained inputs and withdraws stale drafts. Select a retained resized input, **Review native sample**, inspect the reviewed carrier/sample size changes and optionally load **Reviewed Proposed** PCM, then **Apply reviewed sample**. Apply commits one shared history command. **Review retail restoration** stages restoration of that ordinal's Retail sample; Apply commits the restoration. Undo recovers the prior binding rather than treating Clear as a previous-layer toggle. Discard leaves Current unchanged.

Retail, Current and reviewed Proposed remain separate. Current row positions and sizes come from the reconstructed size table, with both bank/entry offsets and the complete carrier extent shown. Each PCM response must match the selected layer's full entry hash/extent, actual sample row/position and sample hash. Shared PCM decoding independently verifies the byte hash and every waveform envelope bin before preview. Playback and preview WAV export require an explicitly chosen preview rate; input rate is metadata, not a game-rate claim.

Retained original WAV recovery and reviewed registration removal reuse existing guarded controls. A currently bound input cannot be removed. Missing/duplicate/forged receipts, changed source targets, stale authoring keys, invalid extent/position/hash fields and mismatched Proposed reviews cannot publish an actionable draft. Native operations lock the controls; closing releases requests and preview resources. A changed source target requires closing and inspecting the new target, rather than recycling an old source sample during Refresh.

Allocation supports the qualified non-repeating sample rules in the [native backend guide](legaia-audio-native-allocation.md). Encoding is lossy; marker-cut, sustain/repeat and unsupported carrier inputs remain refused. All other Current bank/sequence/sample edits compose through the accepted backend and normal Build path. [Current sequence authoring](legaia-audio-sequence-allocation.md) now qualifies allocated carriers. Old fixed-size Current sample dialogs still explicitly refuse allocation bindings; their offset-aware interoperability remains pending. This mode does not establish driver/SPU residency, hardware or gameplay behavior.
