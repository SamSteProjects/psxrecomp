# Native Animation Interpolation Curves

Open a retained animation asset, choose **Edit retained content**, expand **Frame sequence tools** and choose **Native interpolation curve**. Linear is the default. Ease in accelerates from the first endpoint; Ease out slows toward the last; Smoothstep eases at both ends. The curve applies to **Interpolate authored endpoint axes** and **Stage effective pose interpolation**, including the Complete rigid frame scope. Imported-channel interpolation outside the retained editor remains linear.

Authored-axis interpolation replaces only the matching explicit endpoint axes for the selected rigid object. Effective interpolation samples all six inherited-plus-authored native axes for the selected object or every object in the complete frame. Select distinct output endpoints, stage, then use **Review retained edit**, optional **Preview reviewed content**, and **Apply reviewed content**. Changing the curve withdraws an existing review. The curve selector follows the same pending, source and disposal guards as the retained editor.

Curves modify sampled poses over the existing output frame range. They do not retime the clip, infer cadence, perform quaternion interpolation or change actor world placement. Native translations keep signed twelve-bit limits and half ties toward the larger integer. Rotations keep shortest per-axis paths, positive half-turn ties, sixteen-unit quantization and modulo4096 wrapping. Endpoints, outside frames/objects, frozen donor mapping, opaque nibbles and native metadata retain their existing ownership boundaries.

The backend and client use exact integer ratios: progress is t for Linear, t² for Ease in, 2t−t² for Ease out, and t²(3−2t) for Smoothstep. With at most 512 output frames, integer intermediates remain exact in the client. HTTP staging accepts the optional typed `curve` field (`linear`, `ease_in`, `ease_out`, `smoothstep`). Omission preserves legacy Linear receipts v1/v2; curved selected-object/complete-frame receipts use v3/v4 and bind the requested curve. Clients independently validate all expected sample words and the complete resulting edit set. Only sampled channel edits enter the existing project format; no new runtime or persistent curve field is introduced.
