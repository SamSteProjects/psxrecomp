# Metadata Name Persistence Safety

Saved actor selections, scene placement selections, scene views and script bookmarks now share a bounded authored-name validator. Canonical names retain the existing trimmed 1–80 Unicode code-point limit. C0/DEL controls and surrogate code points are rejected; valid non-BMP characters remain supported. Stable IDs, native values, imported provenance and existing schemas are unchanged. Animation display names already rejected surrogates and were not changed.

A native Town01 reproduction showed that the first three command families accepted an unpaired surrogate into in-memory metadata, then Save failed with `UnicodeEncodeError`. The saved project document remained intact, but that name could make later metadata serialization fail. Validation now rejects the name before publishing a create/rename or adding history. Persisted malformed names refuse Open instead of becoming usable project state. The same field validator protects script-bookmark names; script source inspection and qualification remain separate.

Offline checks passed on 2026-10-08: 42 focused Python cases covered the new shared validator and existing actor/scene selection, scene-view and bookmark workflows. Added checks exercise invalid creates/renames with complete document/Undo/Redo equality, controls/surrogates and scalar Unicode bounds, valid Unicode Save/independent Open and Undo/Redo, malformed persisted-name refusal and unchanged native Build/scene inputs. Bookmark source inspection is mocked in these focused name tests; this is not a new script-byte or gameplay qualification claim.

A private native Town01 HTTP run exercised actor/scene selections and scene views. Fifteen surrogate/control requests returned HTTP 400 without changing project state/history/imports/database/files. Valid Unicode names across those three collections saved and reopened independently. Three Undo steps restored the original saved file hashes and native Build inputs, leaving three legitimate Redo entries. HTTP helpers closed. Its initial harness used the wrong Save route; after that request was rejected, the terminal helper was closed and the harness was corrected to the editor's existing `/api/project/save` route before the passing run.

Evidence: `local-output/sdk-20260909/metadata-name-safety-20261008/` (`before-result.json`, `saved-result.json`, `cleanup.json`, private fixture and runner). No browser UI change, package Build, native recompilation, game or runtime attachment ran. This persistence fix needs no gameplay verification; the full SDK goal remains active and solo development continues. Other authored-text fields were outside this focused patch.
