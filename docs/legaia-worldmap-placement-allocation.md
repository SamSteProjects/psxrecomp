## Native Decoration Allocation Review — 2026-10-10

This is the native allocation and read-only SDK Review foundation for new World placement authoring. It clones a complete Current walk-decoration donor into a distinct unused zero-filled MAP record, binds that record to a currently model-free walk-visible cell, and gives the clone a stable authored placement UUID. It does not yet expose project Apply, persistence, Current scene graph composition, editor controls or allocation-enabled Build. Scripted NPCs and placed landmark actors are separate unfinished authoring families.

The pinned Andrew revision `d6e64c68ede25813d35db20980da82a1a025549b` was reread locally: `crates/asset/src/field_objects.rs` supplies the low-nine-bit object grid owner, 512 native records, draw/placed gates, walk-visible cell bit and record terrain selectors; `kingdom_bundle.rs` supplies the existing kingdom carrier context. The adapter retains the existing hash-qualified MAP and floor LUT source path. Native source bytes and complete independent candidate comparisons remain the authoritative serialization evidence.

The grid selects both placement data and terrain tile/page/CLUT. Whole-record donor copying would change the target tile's ground appearance. Allocation therefore copies the complete donor record but preserves the target record's four terrain selector bytes at +20..23, sets explicit signed16 XYZ offsets and low-twelve-bit yaw, retains donor opaque metadata and upper yaw bits, and changes only the target cell's low-nine-bit record index. Upper cell flags, height/floor tables, all other records and unrelated bytes remain identical. Records must be unreferenced by all 16,384 current cells and entirely zero before allocation. Reserved records 0..3 are excluded. Cells anchoring existing resolved or unresolved placements are excluded from the target inventory.

Requests contain exactly `placement_id`, `donor_cell`, `target_cell`, `record_index` and `values`. The values contain exactly signed16 `offset.x/y/z` and `yaw_units` in 0..4095. One to 32 clones are bounded by the 511-placement scene budget, with distinct IDs, native records and cells. Missing donors, occupied or unsupported targets, nonzero records, aliases, out-of-range or boolean indices and extra fields fail before publication. Reopening the complete MAP must preserve every existing source seed and unresolved/excluded coverage while adding exactly the requested native seeds. Review reports distinct authored identity and the native cell-based seed identity without relabeling imported data as authored.

`POST /api/worldmap-placement-allocation-source` accepts exact `scene` and current `source_key`, returning the Current native MAP, floor LUT, decoration donors, unused records and eligible cells. `POST /api/worldmap-placement-allocation-review` additionally requires exact `requests`, returning complete proposed bytes, source/candidate hashes, native record/cell audit and a Review key. Edit mode and source freshness are rechecked around source preparation. Both responses are bounded to 2 MiB and explicitly read-only, project-unchanged and gameplay-unverified; Review is not Build-ready.
