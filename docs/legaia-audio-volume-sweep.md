# Recomp volume sweep audition

Open **Audio → Inspect bank tables → Edit bank parameters → Tone → ADSR1/ADSR2**. Qualify an existing Retail, Current or reviewed Proposed sample/envelope layer, enable **Stereo voice gains**, then choose **Recomp register sweeps** in **Stereo volume mode**. Enter explicit left/right u16 register words and signed16 starting levels. Play renders stereo; **Save envelope preview WAV** includes both words and starting levels in its filename. Monitor volume affects playback only. Mono remains the default and static direct-register stereo remains available.

The bounded `recomp-sweep-counter-v1` model mirrors the unchanged `sweep_env_write`, `sweep_env_step`, `chan_volume` and `calc_vc_delta` functions in `runtime/src/spu.c`. A write resets each divider to zero. Bit15 selects sweep; bits14/13/12 choose exponential/decrease/negative phase, and bits6–0 encode the rate. Bits11–7 are ignored by the recomp. Direct-register words replace the starting level; sweep words preserve it until a counter update. Wrong-sign and frozen initial levels follow that exact implementation. Each output sample steps both counters before applying signed `floor(sample * gain / 32768)` and signed16 saturation.

This preview uses a continuous active-mix clock at 44.1kHz over its entire window. Native counter progression depends on whether the global mix has an active voice; this isolated preview does not infer global voice activity, the game's register writes, instrument pan/gain, note velocity, master volume, reverb, other voices, CD/XA or driver scheduling. The recomp's phase/sign-domain choice is explicitly unverified against hardware. Starting levels are supplied by the user, not read from a running game. This model therefore qualifies offline recomp arithmetic, not game or hardware audio parity.

Volume-mode, register and level edits stop playback. Blank, fractional or out-of-range inputs block Play and Save. Loading/starting and unavailable-source states lock the controls. Existing source ownership, disposal and stale-response guards remain in force. New tone/proposal configurations reset to mono/static defaults. Preview settings create no authoring commands and do not persist or alter bank bytes, project history or native Build inputs. Reviewed Proposed ADSR continues to use qualified Current sample bytes.

`audio-volume-sweep.js` accepts immutable whole-frame mono PCM up to 220500 frames and returns interleaved signed16 stereo. It shares the existing envelope counter-delta arithmetic without changing ADSR calculations. The SDK server serves the module; no runtime implementation is changed.
