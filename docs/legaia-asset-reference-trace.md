# Recorded project relationship tracing

Open **Inspect asset references**, then **Trace project relationships…**. Choose **Dependencies** (outgoing) or **Referenced by** (incoming), one through four hops, and an explicit recorded layer. Press **Trace recorded relationships** to inspect a fresh, qualified project graph across imported scenes. Each displayed row shows the asset chain, its stopping reason, an Inspector action for the last available target, and expandable provenance for every hop.

The trace expands one canonical first path per identity. Parallel edges, cycles and alternate arrivals remain rows rather than causing repeated expansion. Existing node/edge provenance and scene availability are retained; unavailable targets cannot be inspected or expanded. Depth stops, already-seen identities, unavailable sources and node-budget stops appear explicitly. At most128 rows and32 expanded neighborhoods are returned, with a count of adjacent edges omitted by budgets. Responses exceeding8 MiB reject rather than claiming completeness.

These are recorded edge chains. Combining Retail, authored and Effective edges does not produce a resolved Current dependency graph. A chain does not establish actual runtime use, successful scheduling, residency, activation or gameplay reachability. Imported scenes with unavailable decoded resources keep the existing per-scene reasons. Unvisited or unsupported relationships remain outside recorded coverage.

Every expanded neighborhood passes the existing Project reference decoder. The trace decoder then verifies source key, root, direction, depth/layer, path endpoints, each edge's orientation and ownership, consistent duplicate metadata and supported stopping reasons. Changing controls withdraws the report and download. Loading, source drift, close, abort and request-generation checks guard responses and actions. Closing returns to the existing reference explorer. **Save full trace report** retains all accepted paths, qualified neighborhoods, coverage and limitations; it does not modify the project.

POST `/api/asset-reference-trace` accepts exactly `asset_id`, `direction` (`incoming` or `outgoing`), integer `depth`1..4, `layer` (`all`, `imported`, `decoded`, `authored` or `effective`) and `expected_source_key`. Controls and stale keys reject before discovery. Existing reference requests keep their public neighborhood contract; a private full-graph adapter reuses the same verified project discovery and detached catalogs. No new retail structure or runtime dependency is inferred.
