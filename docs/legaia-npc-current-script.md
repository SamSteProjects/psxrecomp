# Current NPC Script Preview

The NPC inspector and Asset Details expose **Inspect Current NPC script** alongside the separate Retail donor and saved Build views. This view composes independently owned script edits before Build, using the same source-qualified native serializers. It changes no project or game state.

The SDK first verifies the current draft and freshly inspects its Retail donor. The authoring context must match that exact source span, entry, full bytes and SHA256. Dialogue, movement, facing, one-byte flags, system selectors, waits and model selectors compose through the established NPC branch baseline. Effect colors compose with overlap refusal. Owned branch words compose last; original anchors are independently redecoded, including unvisited anchors. Partial decoder coverage remains partial.

The record retains its donor header and offsets. Initial appearance, position, allocated record identity, generated P2 spawn rebasing and scheduling are outside this script-body preview. Use the saved Build inspector for emitted package bytes. Current record bytes do not establish execution, runtime residency, native bank capacity or gameplay behavior.

`POST /api/npc-current-script` accepts exactly `entity_id`, naming an active-scene NPC draft. Its `legaia.npc-current-script.v1` response includes the draft, immutable donor inspection, Current inspection, changed-byte count and clone-specific state key. The client checks fresh project/draft ownership, source metadata, inherited header, full Current byte SHA256 and changed-byte count before rendering. Unsupported addresses/paths/extra request fields refuse.

Current instructions use the existing source walkthrough and hypothetical flag/wait sandbox. The context uses the established authored-current flow proof, bound to the clone-specific state key and exact report hash. Scenario exports and replay require fresh endpoint requalification. Unknown system selectors remain Unknown until the user supplies an explicit assumption; no Live values are substituted. Changed project or donor bindings withdraw controls, and Close aborts requests and disposes walkthrough helpers.

It frames the selected target scope without moving the NPC or modifying the project.

Source changes, Clear and replacement overlays invalidate the old callbacks. Marker reference Y does not replace unknown script Y or the NPC's sampled scene elevation.

Current NPC destination editing

Select a qualified MOVE_TO or NPC_RUN instruction in Current inspection, either directly or through **Inspect target** in the viewport. In Edit mode, **Edit selected NPC destination** opens the existing movement editor at that exact PC. Its independently decoded movement source must match the Current NPC owner, donor record, source key and effective X/Z coordinates. Live mode, stale ownership/source, missing capability, unsupported instructions and busy operations disable this action.

Use the movement editor's existing **Review NPC script movement** and **Apply NPC script movement** controls. Review leaves the document unchanged; Apply makes one Undo step and opens fresh Current inspection at the same instruction. **Return to Current NPC script** returns without applying. Viewport layer, scope and explicit reference Y are retained when returning from marker inspection; old overlays withdraw after a source change. Script operand changes remain separate from NPC placement.
