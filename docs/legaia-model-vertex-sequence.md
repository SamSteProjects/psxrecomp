# Vertex Transform Sequences

The SDK can now review and apply a bounded sequence of supported vertex-group operations as one model replacement and one project history entry. The editor composer stages the ordered sequence locally, previews it against Current/Retail geometry and in the scene, and publishes only after explicit Apply.

A sequence fixes one asset, Current object and unique group of 1–4096 object-local vertex indices. It contains 1–16 ordered steps, each with exact `operation` and `values` fields. Supported steps reuse the existing native serializers: `translation` (offset), `alignment` (axis/anchor), `distribution` (axis), `scaling` (percent/pivot), `axis_scaling` (percents/pivot), `rotation` (axis/quarter_turns/pivot), `rotation_angle` (axis/angle_units/pivot) and `grid` (axes/spacing). Values keep their existing bounds and source-coordinate conventions. Pivots support origin, the selected bounds center recalculated at each step, or explicit signed16 XYZ.

Every step operates on the previous step's rounded native words. This is sequential editing, rather than combining floating-point matrices and rounding once at the end. Intermediate overflow or an invalid late step rejects the whole request. Intermediate bytes remain detached; only the final audited candidate can publish. Normals, topology, padding, unselected vertices, other objects, allocation ownership and imported provenance remain fixed. The original inspected Current hash is checked before processing; each intermediate candidate retains native layout qualification. No-op final results create no history entry.

Review uses the existing `/api/model-object-preview` or `/api/model-object-scene-preview` operation `vertex_sequence`, with `values` containing exactly `indices` and `steps`. Apply uses `/api/model-vertices-sequence` with exactly `asset_id`, `object_index`, `indices`, `steps` and `expected_sha256`. The ProjectService method is `transform_model_vertices_sequence`. The final replacement uses the existing model override, history, persistence and Build pipeline; no project schema or runtime transform field is added.

## Editor Composer

In Edit mode, open **Move model geometry**, choose **Vertex group**, select valid object-local indices and choose **Compose group transforms**. Choose an operation and its values, then **Add transform step**. Repeat for up to 16 steps. Each row supports **Edit step**, **Move step up/down** and **Remove step**; **Remove last step** remains available. Editing restores that row’s exact fields. **Update transform step** validates the entire revised sequence; **Cancel step edit** keeps the original row. Staging is disabled during an unfinished step edit. Reordering or removing a step also validates every intermediate native result, so a newly overflowing sequence is refused without changing its previous queue. Bounds-center pivots are recalculated from the selected vertices at that point in the sequence. Explicit pivots use native object-local source XYZ. Custom angles use the existing nearest 1/4096-turn convention.

**Stage transform sequence** closes the composer and creates a local geometry draft. Inspect Current/Retail/Draft and single/all model-instance scene comparisons, then return to the draft. **Apply vertex transform sequence** publishes one model replacement and one history entry. Canceling the composer creates no draft or command. Invalid steps retain the previous valid queue; changed source/context or busy work disables staging. Discard, Undo/Redo and Save/Open retain the existing model workflow. No reusable sequence asset or project schema is introduced.
