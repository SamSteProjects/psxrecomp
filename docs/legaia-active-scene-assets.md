# Active Scene Model Membership

The Asset Database's Active scene resources scope previously listed every imported model in the Project. After importing another scene, models from the earlier scene appeared under the active scope. Shared model IDs used the first imported record's provenance, which could differ from the active scene's recorded variant.

Project state now exposes active_scene_assets separately from the retained Project-wide assets list. AssetDatabase.scene_models projects the selected scene's imported metadata through the same normalization used by ingest, in an isolated database. Each model record carries the selected scene identity and that import's source record, including shared IDs. No identity-prefix membership guess or source-record splice is used. State serialization does not mutate imported metadata, the Project-wide database or authored inputs. An empty Project has an empty active projection. No persistence format migration is needed.

The editor's active model rows consume this projection and retain its scene membership when applying authored overlays. Project resource discovery and its complete variant/membership model remain separate. Catalog scope help now states that models and actors belong to the active import; project-wide authored library entries remain explicitly available. Server model/actor animation support uses active variants, while the compatibility Project-wide assets field remains available.
