# Native SEQ operand codec groundwork

The native codec and persistent SDK command/Build integration are implemented. Editor editing controls are still pending; source inspection, encoded-note timelines and sample audition remain the available browser workflows. Development continues solo; manual gameplay remains deferred.

`importer/audio_sequence_authoring.py` exposes two pure functions. `replace_sequence_operands` accepts immutable Retail and Current SEQ bytes, their reviewed SHA-256 hashes and one to 256 edits. Each edit has exactly `event_offset` and `values`; the offset identifies a fully decoded source event, rather than an inferred note pair or display row. `replace_audio_entry_sequence` applies the same serializer to a standalone SEQ or the qualified sequence chunk of an aligned VAB+SEQ physical PROT entry, and returns native bytes plus an audit.

Channel events accept their existing one or two seven-bit operands (0–127). Tempo events accept one positive 24-bit big-endian microseconds-per-quarter value. Duplicate or unresolved event offsets, boolean/noninteger values, invalid widths and stale hashes reject. Changing a note-on velocity to zero preserves the encoded note-on instruction; subsequent note-timeline interpretation may change. No note endpoints or playback assignments are inferred.

Current bytes must preserve the source header, event shape, status and running-status encoding, delta-time VLQs, channel, boundaries, decoded ticks, complete/partial status and stop location/reason. Changes outside qualified operand spans reject. The serializer independently decodes its output and checks that structural identity again. Tempo changes recompute declared timing; this timing does not prove game playback cadence.

Partial sequences allow edits to fully decoded operands before the unresolved boundary. The entire unknown suffix remains byte-identical, including bytes that might resemble later events. Encoded EOT and post-EOT padding remain unchanged. The carrier wrapper additionally preserves bank/sample chunks, chunk declarations, nonsequence bytes, physical padding and total length. It produces neither a disc patch nor an installed mod.

## Persistent commands and native Build (2026-10-06)

`sdk/audio_authoring.py` stores global source audio identities in `audio_overrides`, with an imported source-scene witness, exact disc/entry/sequence provenance and sorted nonretail event operand edits. It reconstructs Current from retail bytes; binary audio files are not duplicated in the project. Clearing or restoring every edited operand removes the binding. Dirty tracking, authored assets, Undo/Redo, Save/Open, copy/export snapshots and authored Build input keys include this collection. Empty audio state preserves prior project and Build input identities.

`POST /api/audio-sequence-authoring` requires exactly `asset_id`, `expected_entry_sha256` and the resource `expected_source_key`; it returns separate Retail/Current inspections and a fresh `authoring_key`. `POST /api/audio-sequence-review` requires exactly `asset_id`, `expected_entry_sha256`, `expected_authoring_key` and `edits`. Review returns a native operand audit, proposed binding, no-op status and `review_key`, without mutation. The `set_audio_sequence_operands` project command requires those review arguments plus `type` and `review_key`, and requalifies the whole proposal before one history entry. `clear_audio_sequence_operands` requires `type`, `asset_id`, `expected_entry_sha256` and `expected_authoring_key`; it verifies the existing source before clearing one complete resource override.

Build freshly reconstructs each entry, independently encodes the requested spans, compares the full candidate, verifies its physical PROT/disc extent and emits an expected-source-hash overlay. Existing overlap checks reject ambiguous delivery; PROT relocation composes the same qualified entry edits before rebuilding the archive. Reports retain encoded before/after operands, event offsets and native entry spans; labels describe audio sequence operands rather than actor placement.
