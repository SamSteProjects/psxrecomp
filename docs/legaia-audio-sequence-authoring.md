# Native SEQ operand codec groundwork

This checkpoint qualifies a serializer for native audio entries. It does **not** enable audio authoring in the SDK editor or native Build yet. Source inspection, encoded-note timelines and sample audition remain the available editor workflows. Development continues solo; manual gameplay remains deferred.

`importer/audio_sequence_authoring.py` exposes two pure functions. `replace_sequence_operands` accepts immutable Retail and Current SEQ bytes, their reviewed SHA-256 hashes and one to 256 edits. Each edit has exactly `event_offset` and `values`; the offset identifies a fully decoded source event, rather than an inferred note pair or display row. `replace_audio_entry_sequence` applies the same serializer to a standalone SEQ or the qualified sequence chunk of an aligned VAB+SEQ physical PROT entry, and returns native bytes plus an audit.

Channel events accept their existing one or two seven-bit operands (0–127). Tempo events accept one positive 24-bit big-endian microseconds-per-quarter value. Duplicate or unresolved event offsets, boolean/noninteger values, invalid widths and stale hashes reject. Changing a note-on velocity to zero preserves the encoded note-on instruction; subsequent note-timeline interpretation may change. No note endpoints or playback assignments are inferred.

Current bytes must preserve the source header, event shape, status and running-status encoding, delta-time VLQs, channel, boundaries, decoded ticks, complete/partial status and stop location/reason. Changes outside qualified operand spans reject. The serializer independently decodes its output and checks that structural identity again. Tempo changes recompute declared timing; this timing does not prove game playback cadence.

Partial sequences allow edits to fully decoded operands before the unresolved boundary. The entire unknown suffix remains byte-identical, including bytes that might resemble later events. Encoded EOT and post-EOT padding remain unchanged. The carrier wrapper additionally preserves bank/sample chunks, chunk declarations, nonsequence bytes, physical padding and total length. It produces neither a disc patch nor an installed mod.

Validation on 2026-10-06: ten focused Python checks passed without skips, including existing SEQ inspection checks. All 83 supported retail sequence carriers round-tripped an actual channel operand edit and exact restoration; the one partial carrier retained its original decode boundary and suffix. Independent expected-byte construction confirmed that only the selected operands changed. Fixtures cover all channel shapes, running status, tempo timing, composition against Current, no-op, malformed edits, stale hashes, forbidden status/header/delta/padding changes, standalone SEQ and split sound-pack ownership. Evidence: `local-output/sdk-20260909/audio-sequence-authoring-codec-20261006/focused.log`.

Next integration must add persistent source-qualified audio overrides, atomic commands/history, Save/Open and copy validation, Retail/Current/reviewed Proposed UI layers, Build input keys and native overlay composition, then independently read emitted package entries back. These are open work, not acceptance claims from this codec test. Scene assignment, bank authoring, synthesis, XA and game playback verification also remain open.
