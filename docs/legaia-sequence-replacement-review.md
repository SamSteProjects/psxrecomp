# Native Sequence Replacement Review

Open a native audio asset's Details, choose **Inspect sequence events**, then **Edit sequence operands… → Review replacement MIDI…**. Choose a complete supported format-0 MIDI. The SDK constructs a native candidate from fresh Current audio and the browser independently checks its decoded header/events against the upload. The panel shows changed event/tick counts, native carrier/SEQ sizes, candidate hash, preserved opaque tail, added alignment and an encoded note timeline.

This is a read-only prerequisite for general native sequence replacement. It does not apply the candidate, retain a replacement input, create history or deliver a Build. The existing matching-layout MIDI operand Review/Apply remains available independently. The writable workflow is now available through **Edit sequence replacement** in native audio Details; runtime playback qualification remains unfinished.

## Supported Candidate Generation

The complete format-0 parser permits bounded metrical PPQN, seven channel-event families, positive tempo events and a complete ending. Initial tempo and time-signature anchors describe the native header. Timing, event insertion/removal and initial header values can change. Initial time signature requires numerator 1–255, denominator power 0–7, and the supported interchange values 24/8. Mid-track time signatures, unsupported metadata, system/SysEx messages, incomplete tracks and unknown Current native events refuse rather than losing data.

The native writer preserves the Current header variant/version. Changed tracks use explicit native channel statuses and canonical delta VLQs; therefore even one timing edit can increase the sequence size when Current used running status. A logically unchanged upload preserves every Current byte, including its running-status encoding.

Complete Current opaque SEQ tails are retained as exact bytes. Sound-pack sequence sizes stay four-byte aligned; zero to three explicitly reported alignment bytes are inserted before the retained tail after the encoded ending. The writer does not infer that existing opaque tail bytes are disposable padding. Bank/sample chunks and the physical carrier suffix remain byte-exact. Standalone SEQ carriers need no added chunk alignment. Full entry/sequence bounds, native header/event readback and source hashes qualify the candidate.

## Freshness and Remaining Integration

## Writable Native Sequence Replacement

In a native audio asset's Details, choose **Edit sequence replacement**. Wait for Current qualification, choose a supported MIDI under **Review full sequence MIDI**, inspect the counts/sizes/hash and candidate note timeline, then choose **Apply reviewed sequence replacement**. **Refresh sequence replacement** discards a pending review. **Clear native sequence replacement** removes the active replacement; its original input remains for Undo/Redo.

Apply retains the exact uploaded file under `Authored/Audio/SequenceReplacements/<sha256>.mid`. Its binding records retail scene/source ownership and the candidate SEQ hash reconstructed independently from retail bytes plus that input. Retail data stays immutable. Replacement construction uses the retail-owned opaque tail, rather than adopting newly accumulated padding from a prior replacement. It then composes into Current bank/sample state. Replacing an active sequence operand override is one atomic history step: Undo restores the prior operand binding and Redo restores the replacement. Retail-offset operand editing refuses while a full replacement owns the sequence; clear it before editing those offsets. Reapplying the same saved replacement is a no-op.

Every Open, Save, history restore and Build qualifies retained file size/hash and independent retail replay. Content-addressed files are never overwritten or deleted. Collections are bounded to 128 native targets and 16 MiB of unique MIDI content. The shared authored asset list, dirty sections, project/source identities and Build identity include replacement bindings. Historical retained operand-MIDI receipts remain independent, and their Current byte comparison now accommodates a changed sequence extent. Replacement input Asset Database indexing/recovery remains a development follow-up.

Native Build preparation combines replacement sequences with existing bank/sample families and handles variable-size whole audio owners through the archive rebuild path. Standalone SEQ and supported sound packs retain the source carrier/header variant and physical ownership; neighboring resources and the complete candidate are requalified. Build sidecars under `sequence-replacement-inputs/<authored_state_key>` preserve exact original MIDI files plus a hashed binding manifest. This uses the existing disabled-by-default relocation package format; runtime activation was not exercised.
