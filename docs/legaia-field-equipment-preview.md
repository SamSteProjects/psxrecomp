# Field Equipment Variant Preview

In progress — 2026-10-11. The existing field-party animation reader excluded template objects 10/11 but did not apply the reference-pinned equipment descriptor swap to a visible group. The new independent `importer/field_equipment.py` reproduces this source operation with an explicitly selected equipment byte. It does not infer the running game's equipment state.

Evidence: unchanged reference pin `d6e64c68ede25813d35db20980da82a1a025549b`, `crates/asset/src/character_pack.rs::equipment_swap`, and `docs/formats/character-mesh.md`. Source slot 0/1/2 overwrites visible group 0/3/5. Byte zero selects descriptor 11 at 0x140; nonzero selects descriptor 10 at 0x124. The copy is exactly 28 bytes. Reference character-record offsets 0x196/0x199/0x19B are retained as provenance only and are not treated as durable runtime pointers.

The codec first qualifies the original relative-pointer TMD and twelve object descriptors, copies one descriptor and independently re-decodes the candidate. Original header/count, all other descriptors and every data-pool byte remain unchanged. Source-selected previews render ten active groups; the full original twelve-entry table remains intact in the projection. Optional idle/walk previews use the pinned field animation stream and the swapped group's selected geometry. Source/equipment choice and source/projected/descriptor hashes are retained in an explicit `equipment_variant` receipt. Geometry remains object-local until an optional rigid pose is sampled. Timing remains reference-derived, not newly observed.

The read-only `/api/field-equipment-preview` route requires exact project path/source key, an imported registered party asset, equipment byte and optional clip/frame fields. It requalifies source bytes and excludes auxiliary/savepoint or foreign assets. Results are `retail_selected_variant`, not authored Current. This service adds no project/history mutation and does not invent texture residency or actor state.

Two focused native/HTTP tests and ten existing importer-animation checks pass. All three party models are tested with byte 0, 1 and 255, including exact descriptor prefix/suffix preservation, unchanged nobj=12, ten active preview groups, literal projected positions/triangles and matching idle-pose base geometry. Bytes 1/255 produce identical native projections. Invalid equipment values, boolean/out-of-range frames, foreign/auxiliary assets, stale project keys and extra request fields refuse; project/history remain unchanged. Nine private projection receipts: `local-output/sdk-20260909/field-equipment-20261011/projection-proof.json`.

Editor variant controls, client literal replay, visual verification and selected-variant export remain required follow-up work. The existing ordinary field pose remains unchanged by default. This does not broaden support for unknown ETMD headers or primitive flags: pinned TMD code confirms the same relative-pointer format already supported, and unresolved formats still require retail evidence. No authoring, Build, recomp compilation, installation, game or attachment ran. The full SDK goal remains active and gameplay deferred.
