# Inspection Selection History

Hierarchy **Back selection** and **Forward selection** revisit inspected SDK entities in the active project/scene. History includes imported actors, NPC drafts, static scenery, source resources and placement groups, retaining the active member of a group. Restoring a selection clears hierarchy search, expands the necessary folds and reveals the active row. It leaves the camera, visibility and authored data unchanged.

History is ephemeral, limited to 64 entries, and resets when project or scene changes. Repeated renders of an unchanged selection do not add entries. Selecting a new entity after going back truncates the forward branch. This navigation history is distinct from authored Undo/Redo and saved selection groups; it is not written into project files.

Entries retain identities, not old content or runtime addresses. Restoration resolves current SDK entities and source resources and uses existing selection paths. Missing placements/resources, unavailable geometry, busy state, Live mode and source changes during asynchronous selection prevent a stale restore. History cursor completion requires the same scope/revision and exact target entry; transient render selections during restoration are suppressed. Current authored values are displayed when revisiting an entity. History does not restore a previous pose, native byte payload or gameplay state.

## Reveal Selection Availability

The normal actor-selection API renders the hierarchy while the request is busy, then clears busy state afterward. Previously, Reveal selection's availability was recalculated only during that busy render, leaving it disabled after the selection request completed. The editor now uses one shared availability/title updater after busy-state changes and during hierarchy rendering. Selection and existing Reveal semantics are unchanged.
