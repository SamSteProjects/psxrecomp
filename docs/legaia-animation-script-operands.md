# Animation Script Operands

The fixed native writer, authored Project service, HTTP Review/Apply and normal Build integration are implemented. Undo/Redo, reset/no-op behavior, Save/Open and complete native package readback are qualified. Editor forms and direct Current navigation, clone-owned NPC editing and portable operand/preset transfer remain pending. This is a functional API and Build workflow, not completed editor or gameplay acceptance.

`ScriptAnimationOperands` keeps authored entries separate from imported facts. `/api/script-animation-operands` exposes qualified source targets; `/api/script-animation-operand-review` accepts an owner, target and exact values (or null to reset). Review is immutable and compares complete Current/Proposed records while retaining other authored script families and branch words. The `apply_script_animation_operands` command recomputes Review and requires its fresh key; one changed component produces one Undo step. Identical saved requests add no history. Active-scene and Edit-mode guards apply to authoring, and stale requests are refused.

Build composes original-owner edits into compressed MAN output, appended NPC preparation and raw streaming carriers. Complete requested instructions, including no-ops, stay protected against overlapping edits. Reports identify the target operand and native field rather than attributing a script change to an animation clip asset. Imported actor Inspector counts and the Authored Browser expose the new component. Existing operand-file and bundle exporters explicitly refuse an affected owner/scene until transfer support is implemented, so they cannot silently omit these new authored arguments.

Fifteen unique focused Python cases passed across the workflow, native writer and existing Project regression suites with Retail enabled where required; final runs had no failures, errors or skips. The new API checks cover HTTP source/Review, typed fields, immutable Review, keyed Apply, one-step history, no-ops, reset, stale/Live refusal, Save/Open, native composition and transfer omission refusal. Town01 P2 model/frame/tween and Map02 P1 effect-trigger edits passed normal Build and independent complete decoded MAN equality, package directory/ZIP byte equality and saved receipt/audit/manifest/source-file verification. Private copied fixtures were reopened and their saved Build artifacts verified again. A separate actual Map02 appended preparation matched the complete expected MAN after table growth, retained the independent clone and left Project/history/imports unchanged; it was not packaged in that check. Raw streaming delivery for these operands has not yet been demonstrated.

These names describe encoded instruction arguments. Numeric model/effect arguments are not resolved SDK asset or clip identities. Frame/tween units, valid content ranges, host effects and animation playback remain unverified. The variable-length ANIMATE instruction remains outside this writer until its element layout and ownership are implemented.

`integrations/legaia/importer/animation_operand_authoring.py` reuses verified MAN source ownership. Stable target IDs derive from scene, P1 actor/P2 script owner and four-digit hexadecimal instruction PC. A record must have no unknown or conflicting reached-path decoder stops. Edits require an exact field set and strict integers within native widths; booleans are rejected. No rounding, clamping, opcode replacement or guessed clip binding occurs.

Each changed field receives an audit with its source identity, context, PC, before/after values, byte extent and record/MAN hashes. Complete instruction layout and continuations remain unchanged. Original source buffers are immutable. Multiple independent instructions in the same record compose without erasing earlier edits.

The appended-MAN path rebases existing source owners after table growth, verifies unique record ownership and unchanged record extent, and checks the entire source instruction preimage even for a no-op. Only audited changed field spans are copied. Added NPC scripts themselves are not editable through this original-owner API.

Four focused Python tests passed with the private Retail disc enabled, with no failures, errors or skips. Synthetic checks cover ordinary/extended dispatch, all field widths, exact literal bytes, independent instructions in one record, appended rebasing, immutable no-ops, altered selector/context/preimage refusal, aliases, unknown/unreached instructions and foreign identities. The Retail check found 10 qualified instructions in Town01 and 25 in Map02, across both supported families; 92 changed fields matched an independent complete-MAN literal oracle, with MAN structure and all unrelated bytes retained. The boundary values prove encoding integrity, not that those values are valid gameplay content. Unsupported records stayed unavailable; no gates were weakened to obtain coverage.
