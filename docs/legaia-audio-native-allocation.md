# Native audio allocation commands and Build

The native project/backend can now Apply/Clear retained allocation inputs, reconstruct effective audio entries with mixed fixed/allocated samples, inspect dynamically positioned Current samples, preview qualified PCM layers and deliver normal native packages. **The editor allocation controls and complete interoperability with older Current audio tools are still pending.** This is a native backend checkpoint, not acceptance of a completed editor workflow or game playback.

Allocated sample bindings use `sample-wav-allocated-v1` in the existing `audio_sample_overrides` collection. Stable ordinal/receipt rows may include both existing fixed-frame inputs and typed allocation inputs. Bank/source ownership, registered input content and every reconstructed candidate hash are requalified. A binding must contain at least one allocation input; clearing the last one returns remaining fixed inputs to the legacy format. Clearing a selected sample restores Retail rather than recovering an earlier authored layer; Undo recovers that earlier binding. Inputs that reconstruct exact Retail do not create redundant native bindings.

`set_audio_sample_allocation` and `clear_audio_sample_allocation` use detached Review and exact source/authoring/review keys. Apply accepts only `legaia.audio-sample-allocation-source.v1` receipts. One command commits one existing sample-override history step. Review, Proposed preview and no-op Apply leave the project unchanged. Undo/Redo, Save/Open and existing project validation use the shared binding representation; no new top-level collection is introduced.

`POST /api/audio-allocation-authoring` returns Retail and Current sample rows, the actual Current byte position/entry size and waveform, retained allocation inputs and the currently bound historical input. `/api/audio-allocation-review` returns complete before/after entry and selected-sample identities, sizes/positions and the proposed binding. `/api/audio-allocation-preview` requires an explicit Retail/Current/Proposed layer and expected sample hash; Proposed additionally binds its fresh Review. It reopens native bytes and returns hash-qualified mono PCM without choosing a game rate or changing the project. Exact HTTP fields, source keys, strict ordinals and stale/forged/layer mismatch refusal are checked.

Current composition first merges verified fixed bank/SEQ operands, then reconstructs fixed sample receipts at their source spans, then repacks allocated samples. Current references and retained WAV dependency inspection locate samples from the rebuilt size table and pieces. Old offsets are not used against grown pools. The original source record remains immutable. Other fixed sample inputs, program/tone/header operands, following SEQ bytes, reserved table words and opaque tails remain held according to their qualified ownership.

Normal Build calls `audio_composition.prepare_native`. Existing fixed entries retain their overlay path. An allocated owner composes all its audio families into one exclusive `audio-sample-bank` resource request. It removes that owner's separate overlays before archive allocation. Build independently decodes each authored sample, recomputes PCM/error hashes, verifies retained inputs and source/end/start/tail semantics, then reconstructs the complete bank and native carrier from fixed-family baseline bytes. The final request qualifies the complete physical Retail preimage. Source programs/tones/counts, unselected samples and following SEQ/opaque bytes cannot be silently borrowed or overwritten.

The existing physical-owner writer and disabled-by-default native relocation-package format handle both growth and shrinkage. Growing a carrier adds whole sectors and remaps later archive/ISO locations. Shrinking keeps the old physical allocation and zero-fills the space after the complete candidate. This is native structural qualification; driver/global SPU residency, hardware behavior and gameplay audio remain unknown.

Four retail-enabled native command/HTTP checks and ten existing retained-input/sequence checks passed with no skips; eight Python files passed AST validation. Acceptance includes pure sample-only allocation, multiple ordinal moves, restoring one sample while another remains allocated, Current retained-WAV references, no-op/stale/forged refusal, Retail/Current/reviewed Proposed PCM, exact HTTP routes, history and Save/Open. A separate readonly bank-parameter proposal composed correctly with an allocated Current entry.

Until the editor's allocation mode and offset-aware older flows are connected, fixed-size sample and sequence Current authoring explicitly refuse allocated banks. This avoids silently slicing Current with Retail offsets. Existing stored fixed edits still compose and Build correctly, and Current allocation APIs remain available. Bank scalar proposals preserve the early table/header positions and compose with allocation. Full editor rendering/audition interoperability remains to be verified, including withdrawal of stale drafts and source/Current/Proposed allocation controls.

No allocation UI session, game, attachment, install, runtime change or full-disc export occurred in this checkpoint. No hardware, playback or full regression acceptance is claimed. The full SDK goal remains active; solo offline editor integration continues.
