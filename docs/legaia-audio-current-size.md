# Write a sample while keeping its Current size

Open **Allocate sample** from the source bank Inspector, choose a retained resized WAV input, and enable **Keep Current sample size**. Review now supports a separately qualified Current-size write rather than using the original Retail span. The candidate must have exactly the Current sample extent. Its position and complete carrier size must stay fixed, and every byte outside that sample must remain identical to Current. A different frame count is refused before Apply. Clear remains an explicit Retail restoration operation and may change allocation.

Current-size Review uses `legaia.audio-allocation-review.v2`, operation `apply-current-size`, and a SHA-256 audit of the held outside-sample bytes. The client checks the v2 contract, selected input ownership, reviewed candidate hash, actual Current position and unchanged sample/carrier sizes. Apply uses the new `set_audio_sample_current_size` command and recomputes the complete review against fresh authoring context before committing. The existing retained source receipt and mixed allocation binding remain the persistent representation; no alternate project schema or native encoder was added.

Reviewed Proposed PCM, Discard, no-op suppression, stale withdrawal, Undo/Redo, Save/Open and normal native Build use the existing editor/project pipeline. Existing allocation `apply`/`clear` v1 reviews remain unchanged. The legacy Retail-sized writer remains guarded on allocated banks; the new Current-size mode provides the supported write path there. Typed resized inputs still require qualified non-repeating samples, held original start markers and post-end tails, bounded complete 28-frame blocks, and exact source/WAV ownership. Encoding is lossy and input rate is metadata. Runtime instrument assignment, actual pitch, driver/SPU capacity/residency, audible/hardware parity and gameplay remain unverified.
