# Saved GLB morph pose import

Open a model in the Asset Database, choose **Import GLB mesh**, select a native triangle donor and upload a GLB. The inventory states when saved morph poses will be baked. Existing Review/Apply, Current/Proposed previews, section mapping, retained original GLB/recipe, one-step Undo/Redo and Save/Open remain the authoring workflow. Scale, rotation, offset, source scene and donor edits require fresh Review.

Dense or [sparse](legaia-sparse-morph-mesh.md) FLOAT VEC3 POSITION/NORMAL/TANGENT deltas are weighted and added to their existing base attributes before skin or node transforms, following the [Khronos glTF morph specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#morph-targets). Node weights override mesh weights; absent weights use zero. Weights may be negative and are not normalized. Missing attributes in a target leave their base values intact. Tangents are qualified but have no native packet representation. Native normal normalization, coordinate conversion, winding and material/donor rules follow the existing mesh importer. Sections sharing POSITION but using distinct morph POSITION accessors retain separate baked vertex ownership.

This bounded static import supports at most eight targets per primitive and 8192 source vertices, with existing native face/vector allocation limits. All mesh sections must agree on target count. Weight lists must match that count and contain finite numbers within +/-1000000. Malformed sparse storage, target UV/color data, missing base attributes, malformed counts/types/alignment, unsupported extensions, selected animated nodes and native coordinate overflow reject before mutation. No native morph controls, animated morph sampling, skeletal animation or retargeting are added. The fixed-layout provenance GLB editor remains a separate workflow with its previous morph restrictions.
